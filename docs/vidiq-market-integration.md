# VidIQ market data for AmaanaYT

AmaanaYT uses VidIQ as an optional, read-only research source for verified AmaanaYT gameplay topics. It does not let VidIQ edit YouTube metadata, change visibility, approve drafts, upload videos, or publish videos.

## Enable the integration

1. In VidIQ, open **Account Settings → MCP** and create a read-only API key.
2. In the AmaanaYT Render service, set `VIDIQ_MCP_API_KEY` to that key. Keep it in Render's secret environment only; never commit it or paste it into this repository.
3. Leave `VIDIQ_MARKET_RESEARCH=true` and `VIDIQ_WEEKLY_CREDIT_LIMIT=5`. Set the limit to `0` to disable research; other values cannot raise the hard five-credit weekly cap.
4. Check the admin SEO status. Research stays disabled if the key is missing, the authorized VidIQ account does not list the configured AmaanaYT channel, or VidIQ returns an error.

The client only permits `vidiq_user_channels`, `vidiq_balance`, and `vidiq_keyword_research`, and requires VidIQ to explicitly mark each tool read-only. The integration is pinned to AmaanaYT and its expected owner account; it cannot be redirected to Sweatyclanker with environment overrides. It verifies the owner channel and account, checks the shared VidIQ balance before a paid request, and exits early once the weekly cap is used. Research is cached by normalized query for seven days, and Postgres atomically reserves no more than five VidIQ credits in a UTC week (one keyword-research call) and no more than one paid request in any rolling seven-day window. The rolling window also prevents a spend at the end of one UTC week and another just after the boundary. If the balance is below five or cannot be verified, no paid call is made. Failed paid calls do not retry automatically and consume the reservation for that week. A stale result is never presented as fresh evidence.

## How results affect packages

Keyword estimates are stored as market evidence beside, not inside, the YouTube public-search sample. Candidate phrases are supported only when the complete normalized phrase appears contiguously in the source title, source description, or owner-provided context; model analysis cannot make an unsupported phrase “supported.” Only supported rows are sent to package generation, and the prompt receives an ordinal VidIQ priority rather than numeric search estimates. The model, review gate, and saved audit record use the same score-ranked top 12 supported rows. A below-threshold estimate remains a range such as `<750`, never an exact zero; scalar estimates are explicitly labeled as point estimates without provider-supplied uncertainty. Market data is a prioritization hint, not proof of demand or footage facts. A package is held for owner review only when its selected, publishable title uses a supported VidIQ phrase that is absent from the current title and owner primary keyword. An unused alternative title or thumbnail does not create a hold. Otherwise existing evidence and duplicate checks decide whether normal auto-application is eligible. The YouTube search sample deduplicates video IDs, reports video and distinct-channel counts separately, and aggregates support by channel ID so repeated uploads from one channel cannot inflate the evidence gate. Phrase scores use recurrence and inverse-document-frequency only; view velocity ranks example videos but is not treated as evidence that a phrase causes performance. Distinct channel IDs are a creator-diversity proxy, not proof of independently owned creators. Missing or malformed view counts remain unknown, not zero. An all-zero sample or one that lacks enough distinct channels and positive-view channel IDs cannot supply phrases. This is a triage heuristic, not a significance test. It does not change the Twitch discovery/highlight-analysis state or create/upload videos; it improves packaging of existing public uploads.

To verify a rollout, inspect the admin `/api/seo/status` response for `vidiqMarket.enabled`, `lastReason`, and the weekly reserved-credit count; inspect a package's VidIQ evidence and review flag. Do not infer that a YouTube private draft exists or was uploaded from a VidIQ result.
